# 《Blades of Hex》战役编辑器社区作者指南

本文面向直接使用游戏内战役编辑器的社区作者。你不需要阅读代码，也不需要手写 JSON。本文重点是编辑器里的创作顺序、触发器思维和容易导致流程卡死的细节。

如果你要让大模型直接生成关卡 JSON，请改读同目录的《Blades of Hex战役 JSON 创作 Agent 完整规范》。

## 1. 先理解编辑器的工作方式

一关战役由六部分组成：

1. 棋盘：布局、半径（经典模式）、地形、城市、村庄、行政区和工事。
2. 阵营：玩家、AI、剧情控制阵营、回合顺序、外交、金币、主将和手牌。
3. 单位：兵种、阵营、剧情将领、生命、士气、初始行动状态和位置。
4. 开场设置：关卡标题、天气、AI 难度、玩法机制、单位组、调查点和变量。
5. 目标：玩家当前应该完成什么，以及何时切换、完成或失败。
6. 触发器：当条件成立时依次执行动作，是整个战役剧情的核心。

编辑器保存的是“关卡配置”，测试时会根据当前配置重新建图并初始化战局。每次大改后先点“编译检查”，再开始测试。

## 2. 推荐创作顺序

按下面的顺序工作，返工最少：

1. 写一页剧情流程：开场、每个阶段入口、完成条件、失败条件、结局。
2. 建立全部阵营并安排回合顺序与初始外交。
3. 画棋盘和行政区，再放城市、村庄、工事和单位。
4. 为所有会被剧情引用的单位改好唯一 ID。
5. 建立单位组、区域、变量、调查点和目标。
6. 先写“骨架触发器”，只负责阶段开关和目标切换。
7. 再补对白、镜头焦点、操作锁、增援和数值效果。
8. 编译检查，然后从开场到结算完整跑通；退出测试后再测一次，确认重载正常。

ID 建议只用英文字母、数字、下划线和连字符，例如 `marcus_guard`、`rescue_king_timer`。不要用 `__` 开头；`__` 留给对白跳转值和引擎内部标识。

## 3. 棋盘与行政区

棋盘使用六边形轴坐标 `(q, r)`。打开“显示坐标”再制作触发器，可以显著减少点错地块。

编辑器提供两种兼容布局：

- **经典六边形**：以半径控制棋盘范围。标准对局、旧战役以及未显式选择布局的 JSON 始终使用此模式。
- **无边军事地图**：画布内所有完整六角格都是真实、可操作地块；画布边缘的残缺六角格由系统自动用最近真地块的阵营色和边界延伸填满。

无边模式的边缘残缺格是假地块，只用于消除画布留白。它们不能点击、不能编辑、不能移动到达，也不能被单位、区域、调查点、目标光圈或触发器引用。作者只需编辑完整可见地块，不要为边缘填充手工制作内容。

### 3.1 地形与行动力

基础地形消耗为：

| 地形 | 每格行动力 | 额外说明 |
|---|---:|---|
| 平原 | 2 | 无基础防御加成 |
| 森林 | 3 | 防御提高 5% |
| 山地 | 6 | 防御提高 5% |

天气和剧情效果还可能修改移动成本。凡是开启“棋盘操作锁”并指定移动目的地，都必须在真实兵种、真实地形和当前天气下亲自走一遍。目标格可见不等于可达。

### 3.2 城市、村庄与行政区

行政区不是逐格独立拥有阵营。每个 `行政区 ID` 必须有且只能有一座城市作为颜色与归属来源：

- 城市改变阵营时，同一行政区的全部地块一起变色。
- 没有城市的行政区会显示为中立，并在编译时警告。
- 同一行政区有两座城市会造成颜色来源冲突，编译不会通过。
- 村庄只隶属于行政区，不是该区颜色来源。
- 空城不等于可以直接走进：城防 HP 大于 0 时敌军无法进入任何城内格，必须先攻城把城防磨到 0；城防归零后才允许进城巷战，踏上城市中心格才算占领。

先放城市并确认行政区 ID，再用“区划范围”笔刷修整边界。需要大型城市时，在城市工具的“城市半径”中选择 0–3：半径 0 是单格城（200 城防），半径 1 是中心加一圈共七格（600 城防），半径 2 是十九格（1000 城防），半径 3 是三十七格（1400 城防）。城市永远是正六边形，不再支持逐格涂抹城郭；城郭不能覆盖水域、村庄或其他城市中心，编译时按展开后的坐标检查重叠。

大型城市全城共享一个城防血池：攻城或轰炸命中任何城内格（中心或城郭）都削减同一池 HP；城内所有驻军按血池当前百分比获得防御加成，满血 +20%、半血 +10%；血池每回合脱战自动回复上限的 10%。机场、招募和补员仍然只在城市中心格进行；放置城市时可勾选“附带机场”直接建成机场，也可之后用设施工具单独增删。

### 3.3 水域、河流与港口

- “浅水”和“深水”都是无领土颜色的实体水域，舰船可以进入，普通陆军不能进入。
- 舰船只能在港口或水域停留；港口必须是紧邻实体水域的陆地格。
- 河流画在地块边界上，不是舰船占据的水域。溪流增加跨越消耗；普通河流阻断陆军，除非该河段设有桥梁或浅滩。
- 桥梁免除河流阻挡与额外消耗；浅滩允许通过，但仍有额外消耗。
- 编辑河流时逐个吸附顶点，双击结束。桥梁/浅滩必须点在已经保存的真实河段上。
- 旧 JSON 可能带有 `navigable` 字段，但当前版本不据此开放舰船沿河航行；要制作可航行水道，请使用连续浅水/深水地块。

部署单位前先画水域与港口。把水域改回陆地或缩小棋盘时，编辑器会清理失去合法位置的港口和舰船，避免导出后才报错。

### 3.4 工事

- 战壕：对近战攻击防御提高 25%。
- 高射机枪：对远程攻击防御提高 25%，并提供自身防空能力。

普通地面单位也可以从右下角“建设”二级菜单修建战壕、高射机枪或相邻碉堡；工程师不再垄断建设，而是享受折扣、碉堡立即完工，并拥有战地抢修。机场使用城市独立设施槽，可与本格地面工事共存。航母不能在港口直接招募，作者需要把它预置在地图上或用触发器生成。

如果本关关闭“工事系统”，工事可以保留为地图视觉元素，但不要把其规则效果作为通关必需条件。

## 4. 阵营、外交与回合顺序

战役支持任意数量的动态阵营，不局限于红、蓝、绿三方。

每关必须恰好有一个“玩家”控制阵营。其他阵营可设为：

- AI：轮到它时由电脑执行正常行动。
- 剧情控制：不会自行决策，适合等待触发器操控的守军、友军和场景角色。

“参与回合”和“本关启用”是不同概念。一个场景阵营可以启用但不参与回合。所有启用且参与回合的阵营都必须出现在“回合行动顺序”里，顺序由作者上下调整，不由引擎硬编码。

每个阵营还可填写一条“剧情备注”，用于在局内阵营列表的阵营名下补充身份、立场或当前处境。留空时整行不显示；不要把控制方式或是否参与回合重复写进备注。

外交关系只有联盟、中立、敌对三种，并且双向对称：

- 联盟单位互相协助，不能互相攻击。
- 中立单位会阻挡移动，也可以被主动攻击。
- 主动攻击中立单位后，攻击方与该阵营自动转为敌对。
- 敌对单位可正常交战。

“联盟共享视野”是独立玩法开关。联盟不会天然共享视野；是否共享由本关作者决定。

阵营颜色必须从编辑器的九色调色板选择。关卡只保存 `red`、`green` 等颜色选项，主旗色、深色、亮色和地块色全部由规则层统一生成；作者不需要也不应手写颜色数值。单位旗帜、属性栏和战役环形血条会使用统一生成的阵营主旗色与对玩家的外交关系显示。

## 5. 单位、单位组与区域

### 5.1 单位

每个剧情单位必须有稳定且唯一的 ID。以下内容都会引用它：

- 选择、移动、攻击、阵亡和生命条件；
- 操作锁中的允许单位；
- 单位生命、阵营、状态、效果和将领动作；
- 单位组。

初始“本回合可行动”只控制当前回合。若要跨回合禁止移动、攻击或成为目标，使用触发器动作“设置单位状态”。

动态阵营可以正常拥有单位。阵营主将面板只对应传统的 `player1`、`player2`、`player3` 槽位；具体剧情人物应使用“剧情将领库”绑定到单位。

剧情将领分成两层：

- 剧情身份：作者填写稳定 ID、剧情名字和立绘。战场名牌、阵亡日志均使用剧情名字，例如把“百夫长”显示为“马库斯”。
- 玩法原型：可选。选择“百夫长”“尚书”等原型时继承对应属性与技能；留空则是纯剧情将领，没有额外技能或数值加成，但仍拥有将领旗、战场立绘和将领规则身份。

没有专属立绘时选择 `NPC 男性` 或 `NPC 女性`。对白使用带背景版本，战场先锋旗自动使用 `commander_tr` 中的透明版本。一个剧情将领开场只能挂载到一个单位；需要中途登场时，可在“生成单位”或“部署将领”动作中选择同一剧情身份。

### 5.2 单位组

单位组是多个单位 ID 的引用集合，不会生成新单位。适合：

- 一批伏兵中的任意一员攻击玩家；
- 一队守军全部阵亡；
- 给整支小队施加同一效果；
- 统计是否出现减员。

触发器运行中生成的新单位目前不会自动加入编辑器里已有的单位组。需要成组判断的增援，建议在设计阶段明确列出稳定 ID，并分别处理或使用阵营/区域计数。

### 5.3 区域

区域是一组地块，用于“区域内单位数量”。移动条件也可以直接涂抹多个目标地块。能用编辑器图钉或涂抹工具时，不要手工猜坐标。

## 6. 目标、变量、调查点与收藏物

### 6.1 目标

目标状态只有四种：隐藏、进行中、已完成、已失败。

- “开场时显示为进行中”未勾选的目标初始为隐藏。
- 主要目标全部完成时关卡自动胜利。
- 任一可见主要目标失败时关卡自动失败。
- 阶段切换时，先完成旧目标，再把新目标设为进行中。
- 每个目标都可在“任务提示光圈”中用图钉指定跟随单位、独立位置或命名区域。光圈只在该目标处于“进行中”时常驻；目标隐藏、完成或失败后自动消失。

单位、位置和区域可以组合使用：护送任务可同时圈出护送对象与目的区域；调查任务可一次圈出数个证据地块。少量不复用的坐标使用“指定位置”，需要被多个条件或目标复用的地块集合则使用“命名区域”。

例如“攻占主城”转为“防守主城”：在同一个阶段触发器中，将前者设为已完成、后者设为进行中。

“歼灭敌军即胜”和“回合上限”目前不应作为唯一胜负依据。生产关卡应使用明确的单位组、阵营单位数、目标状态或“结束关卡”动作来裁决。

### 6.2 变量

变量分为：

- 本关变量：每次开始或重新测试本关时重置。
- 战役变量：随传记进度保存，适合跨关选择与奖励。

类型有数字、是/否和文本。数字可以设为、增减、乘除、取最小或最大；是/否和文本只能“设为”。

### 6.3 调查点

调查点不是可以隔空点击的按钮。作者必须为它设置一个精确地块，并勾选至少一个“允许执行的特殊单位”；只有名单里的单位实际移动到该格，调查才完成并发出“事件调查点是”。普通单位、相邻地块和命名区域都不能替代这个动作。

调查点的标准制作顺序：

1. 在“收藏物库”创建藏品（若这次交互确实会留下永久线索）。
2. 新建调查点，用图钉点选唯一地块。
3. 勾选允许执行的一个或多个特殊单位。
4. 按需绑定收藏物；焚毁、开门、启动机关等交互留空。
5. 新建或启用一个进行中目标，在“任务提示光圈”的指定位置中标亮同一地块。
6. 用“事件调查点是”承接剧情和目标变化。

第 5 条是创作规范而不是编译器硬限制：调查点处于可调查状态时必须持续高亮，否则玩家无法辨认。若调查点中途开放，就在同一个触发器里同时把对应目标改为进行中。

调查完成后状态自动变为“已完成”。需要再次开放时，用“设置调查点状态”改回“可调查”；重复能力完全由状态控制。

### 6.4 收藏物

收藏物由 ID、名称、Emoji 和剧情说明构成。当前暂时用 Emoji 作为陈列符号。玩家一旦通过绑定的调查点取得收藏物，就会立即永久记录；已登录用户保存到 Frost ID 数据库，未登录用户回退到浏览器 localStorage。

关卡列表右上角的“收藏物”按钮会打开陈列页：未获得条目保持未知，已获得条目可以悬停查看说明。后续关卡可用“已获得/未获得收藏物”条件制作暗线分支与结局判断。

不要把收藏物当成每次任务交互的固定奖励。物件必须在剧情上真的被角色带走：例如马库斯从灰烬中收起帛书残片可以成为收藏物；已经烧光的名册不能反过来成为藏品。

## 7. 触发器的 AoE 式思维

一个触发器包含：

- ID、列表标题和设计备注；
- 是否只触发一次；
- 是否开场启用；
- 条件列表；
- 动作列表。

同一触发器顶层的多个条件是 AND。需要 OR 或 NOT 时添加“满足任一”“不满足”等逻辑条件。

条件分两类；此外还有一种无需条件的开场触发器：

- 事件条件：只在对应事件发生的那一刻成立，例如单位移动、攻击、阵亡、回合开始、对白按钮跳转。
- 状态条件：只要当前状态符合就成立，例如单位存在、生命、金币、变量、外交、目标状态和计时器到期。
- 无条件执行：条件列表留空。勾选“开场启用”时，引擎会在关卡开始时执行；开场关闭时，一旦被另一个触发器中途启用便立即执行，不依赖列表顺序。不需要“关卡开始时”条件。

条件可以为空，动作不能。没有任何动作的触发器没有意义，编译器会直接报错。

复杂剧情应采用“阶段门控”：未来阶段的监听触发器默认关闭，由上一阶段显式启用。

例如：

1. `start_story` 开场启用，播放对白，最后启用 `infantry_ready`。
2. `infantry_ready` 默认关闭，只监听指定对白跳转；收到后启用步兵操作阶段。
3. 步兵完成动作后关闭或自然消费本阶段，并启用 `cavalry_ready`。
4. 后续兵种依次推进。

这样玩家提前点击其他兵种也不会越过剧情阶段。

## 8. 新计时器：以触发器启用时刻为起点

“触发器启用后计时”条件现在遵循以下规则：

- 触发器勾选“开场启用”：从关卡真正开始时计时。
- 触发器开场关闭：直到某个“启用触发器”动作执行时才开始计时。
- 再次执行“启用”会从该动作执行时刻重新计时，即使目标触发器原本已经启用。
- “禁用触发器”会取消当前计时。
- 到期信号在一次启用周期内只会被消费一次；再次启用才能重新装填。
- 默认勾选“只触发一次”最安全。需要反复装填的计时器才取消勾选，并由脚本显式再次启用。

### 8.1 “十分钟内救出国王”

建立失败触发器 `rescue_king_timeout`：

- 开场启用：关闭。
- 只触发一次：开启。
- 条件：触发器启用后计时，`600000` 毫秒。
- 动作：将“营救国王”目标设为失败，或直接结束关卡为失败。

国王被劫的剧情触发器中：

1. 显示被劫对白。
2. 启用“营救国王”目标。
3. 启用 `rescue_king_timeout`。

成功救回国王的触发器中：

1. 禁用 `rescue_king_timeout`。
2. 将“营救国王”目标设为完成。
3. 继续下一阶段。

这样十分钟从“国王被劫”开始计算，而不是从整关开场开始。

### 8.2 “揭示地块”动作

“揭示地块”用于像 AoE2 地编一样，由剧情主动向某个阵营公开战场信息。编辑器中的目标支持：

- 用图钉点选一个单位或单位组：动作发动时揭示其当时所在格，不会持续追踪移动；
- 用图钉直接选一个或多个地块；
- 选择已有命名区域，或用图钉新建区域。

“受益阵营”默认是本关玩家阵营。勾选“永久揭示”时信息不会重新进入迷雾；取消后填写正整数回合数。这个动作只揭示明确选中的格，不会像侦察对策卡那样自动扩张到周围六格。

计时器现在可以和其他条件组合。例如“启用五秒后，并且守军已全灭”会在两者都成立时触发；和事件条件组合时，只接受计时成熟之后发生的对应事件。需要开场立即执行就把条件留空；需要开场延时执行就只添加计时器，不要再额外添加开场条件。

## 9. 对白、连续卡片与跳转

旧版独立“剧情步骤表”已经弃用。现在把多张“显示步骤”动作放进同一个触发器，运行时会按动作列表中的先后顺序自动串联。

注意：同一触发器里的非对白动作会在触发器触发时立即执行，不会等玩家点完全部对白。因此：

- 可以在开场触发器中提前启用精确监听下一跳的阶段触发器。
- 不要假设“设置目标状态”写在对白后面就会等对白结束。
- 真正需要在玩家点完最后一句之后执行的内容，要让最后一句发出唯一跳转值，再由另一个触发器接收。

对白最后一张可填写形如 `__begin_training` 的跳转值。接收触发器使用“按钮跳转值为”条件，并由上一个阶段提前启用。

没有接收者的非锁定对白会淡出并解除残留锁，避免软锁；这只是安全兜底，不应代替正确的阶段设计。

对白卡的“立绘”下拉同时提供全部将领，以及 `NPC 男性（兜底立绘）`、`NPC 女性（兜底立绘）`。没有专属立绘的有名配角应明确选择对应的 NPC 项；不要借用不在场主将的肖像，也不要留空让运行时猜测人物身份。

## 10. 操作锁与高亮

“棋盘操作锁”限制棋盘行动；“对话框点击锁”禁止玩家靠点击对白继续，要求完成实际操作。

每张开启棋盘操作锁的卡片都应有：

- 单位出环：告诉玩家先选谁。
- 地块高亮：放行真正可操作的目标格。
- 提示文字：玩家点错时说明正确动作。

只开操作锁却没有单位或地块，会把全部行动锁住。只高亮单位却不放行移动/攻击目标，也会卡死。

锁定移动流程时务必检查：

- 起点到终点的六边形路径；
- 地形和天气后的真实行动力消耗；
- 中立和其他单位是否挡路；
- 目标格是否被占用；
- 该单位当前是否允许移动或攻击。

如果只是播放剧情而不要求操作，不要开启棋盘操作锁。

## 11. 特殊机制开关

以下机制既能在开场设置，也能被触发器动态启用或禁用：

| 机制 | 常见用途 |
|---|---|
| 对策卡 | 基础教学关关闭，专门教学后开启 |
| 招募单位 | 固定编制、逃亡或守城关关闭 |
| 补员 | 强调不可逆损耗时关闭 |
| 将领主动技 | 按教学进度逐步开放 |
| 天气规则效果 | 只需天气视觉时关闭 |
| 士气系统 | 初学关关闭，士气教学再开启 |
| 工事系统 | 攻城或阵地战教学时开启 |
| 空军指令与舰载机 | 机场扫射/轰炸/空降/侦察或航母登场时开启 |
| 战争迷雾 | 侦察和伏击关开启 |
| 联盟共享视野 | 与“联盟”关系分开决定 |

动态修改机制会立即刷新界面。若玩家当时选中了单位，引擎会清除选择，避免旧操作面板残留。
