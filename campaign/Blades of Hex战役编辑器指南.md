# Blades of Hex 战役编辑器指南

> 面向社区关卡作者与创作 Agent。本文以当前编辑器、Schema v2 校验器和战役运行时的实际行为为准；目标是让一份导出的 JSON 能被可靠地编译、试玩和扩展，而不是只“看起来像配置”。

## 1. 先建立正确的心智模型

一关战役是一个 JSON 配置。编辑器负责生成、校验、导入和导出；运行时负责把它分为四层：

1. 地图与初始单位。
2. 阵营、外交、回合与可开关机制。
3. 目标、变量、调查点等关卡状态。
4. 触发器：监听事件或状态，顺序执行效果。

编剧时最实用的公式是：

```text
可观察事件 / 已满足状态
  → 条件（when）
  → 一次性或可重复的触发器
  → 效果列表（do，按书写顺序执行）
  → 新状态、对白、目标或下一阶段
```

不要把编辑器当作传统 RTS 的“自由脚本语言”。它是一个有明确公共词汇表的状态机。优先使用编辑器已经提供的条件、效果和点选工具；不要让 Agent 发明 `delay`、`flagSet`、`sendMessage`、旧 `steps` 表等未公开接口。

## 2. 推荐工作流

1. 新建关卡，先在“开场与阵营配置”中确定唯一玩家阵营、阵营顺序和机制开关。
2. 在棋盘页先放城市与区划，再画地形、村庄、工事，最后放单位。
3. 给会被剧情引用的单位、单位组、区域、调查点和变量起稳定的英文 ID。
4. 先写主目标和胜败路径，再写触发器。不要等剧情写完才考虑如何结束关卡。
5. 每完成一个阶段就点击“编译”；错误必须清零，警告应当逐条解释或消除。
6. 用“测试”从头跑一次；退出编辑器后再次测试时，系统会以当前 JSON 重建棋盘，仍应验证一次。
7. 导出 JSON 后再保存剧本源文件。不要手改导出文件的结构后跳过编译。

建议的 ID 命名：

```text
单位：marcus, recruit_infantry, target_gate
单位组：north_guard, training_targets
区域：gate_square, forest_pass
调查点：clue_order, cache_01
变量：gate_opened, rescued_count
触发器：intro_start, gate_reached, phase_cavalry
目标：main_hold_gate, optional_no_loss
```

ID 一旦被触发器、单位组或星级规则引用，尽量不要中途改名；编辑器会协助改写大量引用，但导出后手写 JSON 时尤其容易遗漏。

## 3. 开场、阵营与回合

### 3.1 关卡基础设置

| 字段 / 面板 | 用途 | 作者建议 |
|---|---|---|
| 关卡 ID | 稳定的机器标识，只允许字母、数字、连字符 | 发布后不要随意改，否则存档/目录引用会断开 |
| 关卡名称、传记名称、章节标题 | 显示文案 | 用于大厅与战役抬头，不参与逻辑 |
| 随机种子 | 初始随机源 | 测试同一关时固定种子，方便复现 |
| 天气 | 晴、雨、雾、风或标准循环 | 只有“天气规则效果”开启后才会带来规则变化 |
| AI 难度 | AI 阵营收入倍率等参数 | 只对 `controller: ai` 的战役阵营有意义 |
| 初始金币 / 初始手牌 | 各阵营起始资源 | 教学关通常设为 0 并关闭对策卡 |

当前版本的“回合上限”会随 JSON 传入关卡适配器，但战役运行时不会据此自动结束关卡。若需要限回合失败，请用“新回合开始时”条件配合变量、目标失败或“结束关卡”。

### 3.2 阵营是动态的，不限三方

每关可创建任意数量的作者阵营。每个阵营包含：

| 属性 | 含义 |
|---|---|
| `id` | 字母开头，后续仅用字母、数字、`_`、`-`；`neutral` 为系统保留，不能由作者重复声明 |
| 显示名、颜色 | 名称显示在单位/阵营界面；颜色必须从编辑器调色板选择 |
| 控制方式 | `human` 玩家、`ai` 自动行动 AI、`scripted` 剧情回合（短暂停留后自动结束） |
| 参与回合 | 是否进入回合行动顺序；训练靶、背景阵营通常关闭 |
| 本关启用 | 关闭后不能进入回合顺序 |

单人战役必须恰好有一个 `human` 阵营，且它必须等于“玩家视角阵营”。多个敌对、盟军、背景和剧情阵营都可以存在；不要再假设只有红/蓝/绿三方。

### 3.3 回合顺序由作者决定

“回合行动顺序”不是硬编码。它必须包含所有“本关启用且参与回合”的阵营，且不重复。顺序第一位也是每轮锚点：留空阵营的“新回合开始时”条件会在这一方开始时满足。

常用组合：

```text
玩家 → AI 敌军 → 剧情阵营
玩家 → 中立守卫（scripted）→ AI 敌军
AI 伏击方 → 玩家 → AI 主力
```

若只需要某势力占位、阻挡移动或作为训练靶，设置为“参与回合：关闭”最稳妥。

### 3.4 外交关系

两阵营间只有三种关系：

| 关系 | 行为 |
|---|---|
| 自身 | 同一阵营，绿色 |
| 联盟 `ally` | 不能互相攻击，蓝色；是否共享视野由单独的“联盟共享视野”开关决定 |
| 中立 `neutral` | 单位会阻挡移动，也可被主动攻击；首次主动攻击后，双方自动转为敌对，黄色 |
| 敌对 `enemy` | 可以攻击，红色 |

“改变外交关系”是对称操作：设 A→B 会同时设 B→A。它会取消当前选择并刷新棋盘，因此适合用于背叛、停战、收编和剧情伏击。

## 4. 地图与单位

### 4.1 六边形坐标与半径

棋盘坐标使用轴向六边形坐标 `(q, r)`。半径可设为 2–7；一个坐标合法当且仅当：

```text
max(|q|, |r|, |q + r|) ≤ 半径
```

编辑器的图钉/涂抹工具应当是坐标录入的首选。手写 JSON 时，必须检查单位、城市、调查点、区域和触发器目标都在棋盘内。

### 4.2 城市、行政区与领土

城市不仅是收入点，也是行政区的“颜色来源”。同一 `districtId` 的地块会归属该行政区对应城市的阵营；不要把领土理解为可逐格独立指定的阵营色。

- 每个 `districtId` 只能有一座城市作为颜色来源；两座会编译报错。
- 不规则行政区用“区划”画笔覆盖，而不是手改地块阵营。
- 没有城市颜色来源的区划会显示为中立，编译器会警告。
- 空城可以被占领，没有额外编辑器限制。
- “改变单位阵营”只改变单位，不会占领城市或修改行政区。
- “生成单位”只在指定格出现，**不会**顺带夺取该地块或城市。

### 4.3 地形、村庄与工事

| 地形 / 工事 | 实际规则 |
|---|---|
| 平原 | 每移动一格消耗 2 点行动力 |
| 森林 | 每格消耗 3，提供 5% 防御 |
| 山地 | 每格消耗 6，提供 5% 防御 |
| 战壕 | 对近战攻击 +25% 防御 |
| 高射机枪 | 对远程攻击 +25% 防御，并提供自身防空能力 |

**路径先算行动力，再开操作锁。** 例如骑兵有 8 点行动力，平原也只能连续走 4 格；要求它在平原走 5 格的教学锁会让流程无法继续。写“移动到指定地块”前，要同时检查轴向距离、每格地形消耗、天气修正、沿路是否被单位阻挡。

### 4.4 单位、将领与单位组

公开兵种目前包括步兵、骑兵、炮兵、碉堡、无人机。单位可设初始生命百分比、士气、本回合是否可行动与绑定将领。

- 单位 `id` 是触发器、白名单、目标环和单位组的主键，必须唯一。
- `canAct` 是初始可行动状态；若要跨回合永久冻结/恢复，请用“设置单位状态 → 可行动”。
- 每关的阵营主将面板只对应传统 `player1/player2/player3` 槽位；动态阵营若要让单个单位带将领，可直接在该单位上绑定。
- 单位组是复用引用，不是新实体；适合“指定一批援军”“一组守军全部阵亡”“对一组单位施加效果”。

## 5. 特殊规则与关卡状态

### 5.1 机制开关

机制可在开场设置，也能被“启用/禁用机制”动作动态修改。

| 开关 | 适合何时关闭 / 开启 |
|---|---|
| 对策卡 | 前几关基础教学关闭，专门教学关再打开 |
| 招募单位 | 剧情小队、逃亡、守城演出常关闭 |
| 补员 | 想让消耗不可逆时关闭 |
| 将领主动技 | 逐步教学时按关解锁 |
| 天气规则效果 | 只想用天气做视觉氛围时关闭；讲地形/气候时开启 |
| 士气系统 | 初学操作关关闭，士气教学关开启 |
| 工事系统 | 攻城或阵地战教学才开启 |
| 战争迷雾 | 侦察、伏击关开启 |
| 联盟共享视野 | 联盟是否共享视野的独立选择；默认关闭，不会因结盟自动开启 |

不要把“盟军”与“共享视野”混为一谈。两者分别由外交关系和机制开关控制。

### 5.2 目标、胜败与星级

目标状态只有：`hidden`、`active`、`completed`、`failed`。

- `main: true` 的主要目标：全部完成即胜利，任意失败即失败。
- `active: false` 的目标初始为隐藏；剧情时用“设置目标状态”改为 `active`。
- 需要阶段切换时，不要删除旧目标；将旧目标设为 `completed`，将新目标设为 `active`。
- “结束关卡”用于即时、明确的胜利或失败，并可传入结局文本。
- 星级规则：胜利基础 1 星；每满足一条规则 +1，最多 3 星。星级规则应使用最终可查询的状态条件（变量、单位存活、目标状态等），不要依赖瞬时事件。

当前战役模式由目标控制器裁决胜负。编辑器里的“歼灭敌军即胜”不要单独作为剧本胜利条件依赖；想要“全歼”时，写一个“单位组状态 = 全员阵亡”或“阵营单位数量 = 0”的触发器，再完成主要目标或结束关卡。

### 5.3 变量、区域与调查点

变量有 `number`、`boolean`、`string` 三种类型：

| 作用域 | 生命周期 | 典型用途 |
|---|---|---|
| 本关 `level` | 每次进入本关重置 | 当前阶段、临时计数、是否播过台词 |
| 战役 `campaign` | 随战役进度保存 | 分支选择、人物是否获救、跨关奖励 |

数字可设为、加减乘除、取最小/最大；布尔和文本只能“设为”。比较布尔/文本时只用“等于”或“不等于”。

区域是涂抹出的坐标集合，适合“区域内单位数量”。移动事件的目标位置请优先使用编辑器的“目标位置”涂抹列表，不要手写未公开的区域快捷字段。

调查点在可用状态下被玩家点选会触发“事件调查点是”，并变为 `completed`。要让它再次可调查，先用“设置调查点状态 → 可调查”重新开放。当前运行时会在第一次点选后完成调查点，因此不要把面板里的“一次性触发”当作独立的重复交互开关。

## 6. 触发器：作者最重要的工具

一个触发器有：`id`、条件列表 `when`、动作列表 `do`、`once`、`enabled`。

- 同一触发器的多个 `when` 顶层条件是 **AND**。
- `all` / `any` / `not` 可构成嵌套逻辑。
- 事件发生后会尝试评估所有启用触发器；只有状态条件的重复触发器可能在每次事件后反复生效。
- 剧情、奖励、生成援军通常设为 `once: true`。
- `enabled: false` 是分阶段脚本的核心工具，不是失败状态。

### 6.1 条件索引

| 类别 | 条件 | 用途 |
|---|---|---|
| 逻辑 | 满足全部、满足任一、不满足 | 组合复杂判定 |
| 开场 / 时间 | 关卡开始时、计时器到期、新回合/指定阵营回合开始时 | 开场演出、延时、回合剧情 |
| 单位事件 | 指定单位被选中、移动到指定地块/涂抹区域、攻击指定单位/组、指定单位/组被击败 | 教学、伏击、护送、击杀事件 |
| 城市 / 交互事件 | 指定城市被占领、事件调查点是 | 占城、查找线索 |
| 技能 / 卡牌 | 使用指定对策卡、指定单位使用技能 | 机制教学和技能剧情 |
| 对话事件 | 按钮跳转值为、对话选项结果为 | 接收内联对白的 `next` 信号 |
| 单位状态 | 城市/地块归属、单位存在/存活、单位生命比较、单位组状态、区域内单位数量、阵营单位数量 | 目标、守城、全歼、撤离 |
| 全局状态 | 金币比较、变量比较、外交关系、天气、目标状态、调查点状态、机制开关、触发器启用状态 | 分支和阶段控制 |

“对话选项结果”为底层扩展接口；当前编辑器的内联对白公开的是 `next` 跳转。常规作者请使用“按钮跳转值为”，不要假设已有可视化多选对话编辑器。

### 6.2 计时器的正确用法

计时器从关卡激活后开始计时，到期一次。它由独立轮询驱动，不能与需要同一次事件的条件顶层并列，例如：

```text
错误：关卡开始时 AND 计时器到期
错误：指定单位移动到目标格 AND 计时器到期
```

这两个条件不会在同一次事件中同时为真，编译器会阻止这类组合。正确做法是拆为两个阶段：计时器触发对白；对白结束或单位移动后，再启用下一触发器。

### 6.3 动作索引

| 动作 | 实际效果与注意事项 |
|---|---|
| 显示步骤 | 内联对白、旁白、焦点与操作引导；详见下一节 |
| 开启/解除输入锁 | 限制或恢复玩家操作；锁定时必须给出可执行的白名单 |
| 启用/禁用触发器 | AoE 式分阶段编剧的关键 |
| 设置目标状态 | 推进主要/支线目标；完成主要目标会触发胜利裁决 |
| 生成单位 | 指定空格生成，不夺取领土 |
| 修改变量 / 金币 / 单位生命 | 分支、奖励、计数、伤害与治疗 |
| 改变单位阵营 | 单位倒戈；不改变城市归属 |
| 设置单位状态 | 持久控制可行动、可移动、可攻击、可成为目标、无敌、可反击 |
| 施加效果 | 攻防速/生命上限修正、生命阈值、无敌，可设持续回合 |
| 部署将领 | 给指定单位绑定或移除将领 |
| 改变外交关系 | 对称地改变两阵营关系，并刷新界面 |
| 改变天气 / 调查点状态 / 机制开关 | 动态改写环境与可用玩法 |
| 移除/处决单位 | `despawn` 直接离场不算阵亡；`kill` 触发阵亡逻辑 |
| 结束关卡 | 强制胜利或失败，适合明确剧情结局 |

“发送消息”不是单人战役动作，已不属于作者接口。

### 6.4 对白、连续卡片与阶段跳转

旧的独立“剧情步骤表”已弃用。新剧本只使用触发器内连续的“显示步骤”卡片：

```text
同一触发器的 do：
  显示步骤 A → 显示步骤 B → 显示步骤 C
```

运行时会自动把连续的内联卡片串起来：先显示 A，玩家点击后到 B，再到 C。最后一张卡片可以设一个以 `__` 开头的 `next`，把对白链交给下一阶段触发器。

**非常重要：** 同一 `do` 里的非对白动作不会等待玩家点完对白；触发器触发时它们会立刻执行。因此“启用下一阶段触发器”必须写在上一段触发器的动作列表中，而不是幻想它会在最后一句对白之后才执行。

推荐的 AoE 式阶段门控模板：

```json
[
  {
    "id": "intro",
    "enabled": true,
    "once": true,
    "when": [{ "kind": "timer", "value": 1200 }],
    "do": [
      { "kind": "showStep", "text": "第一段旁白。", "boardLock": true,
        "highlight": { "tiles": [{ "q": 0, "r": 0 }], "hint": "观察校场" } },
      { "kind": "showStep", "text": "准备开始。", "next": "__phase_move", "boardLock": true,
        "highlight": { "unit": "scout", "hint": "侦察兵待命" } },
      { "kind": "setTriggerEnabled", "trigger": "phase_move", "enabled": true }
    ]
  },
  {
    "id": "phase_move",
    "enabled": false,
    "once": true,
    "when": [{ "kind": "eventNextIs", "value": "__phase_move" }],
    "do": [
      { "kind": "showStep", "text": "点击侦察兵并移动。", "boardLock": true, "dialogLock": true,
        "highlight": { "unit": "scout", "tiles": [{ "q": 1, "r": 0 }], "hint": "移动到高亮地块" } },
      { "kind": "setTriggerEnabled", "trigger": "scout_arrived", "enabled": true }
    ]
  }
]
```

这套写法的要点：

1. 下一阶段监听器初始关闭，避免玩家好奇点击其他单位越级触发。
2. 上一阶段触发时提前启用它；因为它只监听精确的 `__phase_move`，不会抢跑。
3. 最后一张非锁定卡片点击后发出 `__phase_move`，下一阶段立刻显示单张、等待操作的指令卡。
4. 当前引擎会在非锁定对白的跳转不存在或没有触发器接收时淡出并解除残留锁，同时输出警告；这是防软锁兜底，不是正常流程设计。

### 6.5 操作锁与焦点

`boardLock: true` 会开启严格引导；`dialogLock: true` 会禁止点击对白继续推进，要求玩家完成棋盘操作。

每张开启棋盘操作锁的卡片都必须写完整焦点：

```json
"highlight": {
  "unit": "recruit_infantry",
  "tiles": [{ "q": 1, "r": 1 }],
  "hint": "移动到高亮地块，然后攻击草靶"
}
```

- `unit`：给单位打环，用于“先选谁”。
- `tiles`：高亮且放行指定操作地块，用于移动、攻击、调查。
- `hint`：玩家点错时显示的可读提示。

只写 `boardLock: true` 而没有实际 `unit` 或 `tiles`，会把所有行动锁住并产生警告。只高亮单位而不放行移动目标，也会导致“选中了却走不了”。

操作锁主要拦截移动、攻击等实际行动；不要把“玩家不会好奇点其他单位”当作脚本保证。阶段触发器应默认关闭，等上一阶段显式开启。

## 7. 三个可直接复用的范式

### 7.1 单位进入敌方主城：对白 + 目标切换

```text
条件：指定单位移动到指定地块（百夫长所在单位 → 敌方主城）
动作：
  1. 显示步骤（马库斯台词）
  2. 设置目标状态（“攻占主城” → 已完成）
  3. 设置目标状态（“防守主城” → 进行中）
```

如果第二个目标需要从隐藏出现，初始状态设为 `active: false`，再用“设置目标状态 → active”。

### 7.2 中立护卫被攻击后反目

初始外交把“护卫”和玩家设为中立。中立单位仍会挡路，也能被攻击；第一次攻击会自动转敌对。若剧情需要额外反应：

```text
条件：指定单位攻击指定单位/组（玩家 → 中立护卫）
动作：显示步骤 → 改变外交关系（护卫 ↔ 玩家 → 敌对）→ 启用伏击触发器
```

即使不写“改变外交关系”，主动攻击中立单位也会自动反目；该动作用于让规则与剧情同步得更明确。

### 7.3 受伤首领撤退而非死亡

```text
条件：单位生命比较（首领 HP ≤ 25%）
动作：
  1. 施加效果（无敌或最低生命阈值）
  2. 显示步骤
  3. 移除/处决单位（选择“直接离场”）
  4. 设置目标状态（主目标 → completed）
```

若首领不能死，用“锁下限”或无敌效果，而不是依赖玩家不会打出最后一击。

## 9. 给创作 Agent 的交付约束

当让 Agent 编写或修改关卡时，建议直接给出这份约束：

```text
请只使用 Blades of Hex 编辑器公开的 Schema v2 条件与动作。
输出前必须：

2. 让所有 boardLock 的 showStep 含有 highlight.unit 或 highlight.tiles，且有 hint；
```
