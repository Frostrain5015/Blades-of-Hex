# Blades of Hex — 可选 2.5D/3D 渲染模式接入计划

- 版本：v1.0（设计基线）
- 状态：待评审
- 关联文档：`docs/战场渲染与水域系统升级计划.md`（Pixi 渐进切片策略，本计划与之兼容并立于其上）
- 原型：`prototype/3d-battlefield/`（独立设计原型，见 §9）

---

## 1. 背景与现状结论

当前渲染栈（详见源码：`js/renderer.js`、`js/rendering/*`）：

- **Canvas2D 是全量保真后端**：每帧 `renderGame()` 直接读 `gameState` 单例绘制一切（地形、单位徽章、特效、浮字、迷雾、天气）。
- **PixiJS 8（WebGL）是已接入但初级的第二后端**：仅接管交互提示层与地形贴图合成，由 `battlefieldDelegation` 标志控制回退。
- **渲染边界抽象已存在且成熟**：`types/battlefield-renderer.ts` 定义六方法接口（`initialize / syncScene / enqueue / resize / render / destroy`），`createBattlefieldRenderer.js` 的 `BattlefieldRendererBoundary` 负责后端选择、不可变 DTO、失败自动回退 Canvas2D。
- **快照 DTO 已后端中立**：`buildBattlefieldSnapshot()`（`js/rendering/battlefieldSnapshot.js`）输出棋盘、单位（type/campKey/motion/health/morale/rank/commander/presentation）、交互态，带 `signature` 判脏。
- **单位视觉 = Canvas 程序绘制**（渐变球 + 兵种符号 + WebGL 布料旗帜），**无任何 3D 模型、贴图资产**；特效是 `main.js → effects.js` 的命令式调用，不进快照、不进 `enqueue()` 通道。

**结论**：接入 3D 模式的天然接缝已经存在（与 Pixi 后端同一接口），最大的实际工作量在三处：

1. 从零生产全部 3D 模型与动画资产（当前为零）；
2. 把命令式特效触发点事件化，让非 Canvas 后端可以订阅；
3. 3D 视角下的输入拾取（raycast → tile）与相机系统。

## 2. 目标与非目标

### 目标

- 新增一个**可选**渲染后端 `three-3d`（Three.js / WebGL2），与 `canvas2d`、`pixi-webgl` 并列，由设置界面显式选择，默认不变。
- 3D 模式下：全 3D 棋盘（六棱柱地块、水面、地形高度差）、全部 10 个基础兵种 + 12 个专精变体的模型与动画、5 类攻击表现对应的 3D 特效、天气与环境氛围、完整保留现有游戏逻辑与 DOM HUD。
- 体验**可选且可回退**：WebGL 失败 / 性能档过低 / 上下文丢失 → 自动回退 Canvas2D，复用现有 boundary 回退链路。
- 先交付**设计原型**验证美术方向，再分里程碑接入。

### 非目标（本计划范围内不做）

- 不替换 Canvas2D 后端（它仍是兜底与默认）；不移除 Pixi 后端。
- 不改变任何游戏规则、数值、网络协议。
- 不做 VR/AR；不做自由第一人称视角（相机保持"沙盘俯视角"语义）。
- 3D 模式不覆盖战役编辑器等工具界面。

## 3. 技术选型

| 决策点 | 选择 | 理由 |
|---|---|---|
| 3D 库 | **Three.js**（依赖引入，Vite `manualChunks` 独立分包，懒加载） | 生态最大、WebGL2 成熟、与现有 pixi 懒加载模式一致；包体 ~600KB gzip 前，独立 chunk 不影响默认用户 |
| 美术方向 | **低多边形风格化（stylized low-poly）+ 柔光 PBR-lite** | 与现有"战棋沙盘 + 暗黑黄铜 UI"气质相容；程序化建模可行，降低资产成本；远距离俯视角下辨识度高于写实 |
| 模型生产 | 双轨：**程序化基元建模（代码）打底 → GLTF 资产管线升级**（见 §6） | 阶段 M1–M3 不依赖外部美术即可全量落地；后续可逐兵种替换为美术 GLTF，加载器不变 |
| 动画 | **代码驱动动画系统**（参数化状态机 + 缓动）+ GLTF 阶段升级 skeletal AnimationMixer | 与快照的 `motion{path,startedAtMs,durationMs}` 参数化模型天然吻合，时间轴由快照时间戳驱动，回放/联机零漂移 |
| 特效 | 自研轻量粒子（`THREE.Points` + InstancedMesh + shader）+ 少量拖尾/冲击波网格 | 不引入 three-nebula 等重型粒子库；特效词汇固定且有限（§7），自研可控 |
| 浮字/HUD | 伤害浮字用 canvas-texture Sprite；其余 HUD 沿用现有 DOM | 保持 HUD 一套代码两种渲染模式通用 |
| 后期 | 可选 `postprocessing`（bloom + vignette），性能档 `high` 才启用 | bloom 对"精美感"收益最大；balanced/low 直接关闭 |

## 4. 总体架构

```
gameState ──buildBattlefieldSnapshot(判脏)──► BattlefieldRendererBoundary
                                                  │  backend: 'three-3d'
                                                  ▼
                                    ThreeBattlefieldRenderer (js/rendering/three3d/)
                                    ├─ SceneGraphAdapter   快照 DTO → 3D 场景增量同步
                                    ├─ BoardBuilder        六棱柱地块/水面/地形装饰（Instanced）
                                    ├─ UnitActorFactory    兵种模型 + 动画状态机（每单位一个 Actor）
                                    ├─ FxSystem            攻击特效/粒子/浮字（订阅事件）
                                    ├─ CameraRig           沙盘相机（缩放/平移/限位/焦点动画）
                                    └─ InputPicker         raycast → tileKey / unitId
事件源：enqueue() 通道（攻击/技能/治疗等视觉事件，见 §5.3）
```

### 4.1 接入点（复用现有接缝，改动极小）

1. `js/rendering/renderBackend.js`：`RENDERER_BACKEND` 增加 `THREE_3D: 'three-3d'`。
2. `js/rendering/capabilities.js`：`getRendererPreferenceOrder` 注册偏好链（`three-3d` 要求 WebGL2 + `high`/`balanced` 档，`low` 档不推荐）；WebGL2 缺失时永不入选。
3. `js/rendering/createBattlefieldRenderer.js`：工厂增加 `threeRendererFactory` 分支，动态 `import('three')` 懒加载（与 Pixi 同一模式）。
4. `index.html` 设置下拉 `#rendererBackend` 增加"3D 沙盘（实验）"选项；`js/settingsRuntime.js` 默认值不变。
5. `vite.config.js`：`manualChunks` 把 `three` 独立分包，仅在选中 3D 后端时下载。
6. 3D 后端激活时**绕开混合合成路径**：不创建 Pixi 叠加层、不执行 `renderGame()`（Canvas 全量），`battlefieldDelegation` 对 3D 后端视为全量接管；DOM HUD（`#selectionHud`、动作按钮、`#cardCanvas`）原样保留。

### 4.2 场景同步模型

- 主循环每帧照旧 `buildBattlefieldSnapshot` + `shouldSyncBattlefieldSnapshot` 判脏（现有 20Hz 节流不变），`syncScene(snapshot)` 推入。
- `SceneGraphAdapter` 做**增量同步**：按 `unitId`/`tileKey` diff，仅创建/销毁/更新变化的 Actor；快照不可变（boundary 已冻结），diff 安全。
- 移动动画**不由 diff 驱动**，由快照 `unit.motion{path, startedAtMs, durationMs}` 在 3D 端按同一时间戳重放 —— 与 Canvas 端 `getUnitVisualPos()` 同一参数化模型，保证联机/回放一致。
- **快照补字段**（小改 `battlefieldSnapshot.js`，对现有后端无影响）：
  - `weather`（当前缺失，3D 氛围必需）；
  - 单位 `specialization`（专精变体选模型用）；
  - 攻击预览 `targetCandidates` 已有，补 `attackPreview.presentation`（攻击分类，预览弹道用）。

### 4.3 输入与相机

- `InputPicker`：pointer 事件 → `Raycaster` 对地块网格/单位包围盒拾取 → 产出与 `getTileAtPixel`（`js/input.js:1948` 附近）相同的 `{tileKey}` 写回 `gameState`；上层选中/悬停/目标逻辑**零改动复用**。
- `CameraRig`：斜俯视角（默认俯角 ~50°）、滚轮缩放（限位）、右键/中键平移（软边界）、`F` 聚焦选中单位的焦点动画；提供"2.5D 锁定"开关（锁定旋转仅缩放平移 → 固定轴测观感）。
- 屏幕空间换算：DOM HUD 需要的单位屏幕坐标由 `Vector3.project(camera)` 提供，接入现有 HUD 定位。

## 5. 与游戏逻辑的事件对接（关键改造）

当前特效全部命令式触发，3D 后端不可见。改造原则：**触发点事件化，Canvas 后端行为不变**。

### 5.1 攻击表现（5 类，分类器现成）

`rules/attackPresentation.js` 的 `classifyAttackPresentation()` 已是本地/联机/预览共用的唯一分类器。3D 端按分类映射特效：

| 分类 | 兵种 | 3D 表现 |
|---|---|---|
| `assault` | 步/骑 | 突进 + 武器挥砍弧光 + 命中火花 + 受击后仰 |
| `fire-cannon` | 炮/巡洋舰/岸防炮 | 炮口火光 + 后坐 + 抛物线炮弹（发光拖尾）→ 落点爆炸（粒子 + 冲击波环 + 点光 + 震屏） |
| `fire-tracer` | 碉堡/驱逐舰/无人机 | 曳光弹流（拉伸发光体）+ 命中跳弹火花 |
| `fire-torpedo` | 潜艇 | 水面下直线航迹（尾流气泡）→ 水柱 + 舷侧水花 |
| `fire-air-strafe` | 航母 | 舰载机小编队掠飞 + 扫射弹着点线列 |

### 5.2 事件化改造方案

1. 在 `js/main.js` `_execAttackFx`（约 3136–3185 行）等命令式触发点，**追加** `battlefieldRenderer.enqueue({...})` 视觉事件（类型/分类/攻击方/目标方/是否暴击/坐标），保留原 effects.js 调用一行不动 —— Canvas 后端收到事件可忽略，行为完全不变。
2. `js/visualEventBridge.js` 已有的 `fx:healFlash / fx:explosion / fx:screenShake / fx:rankUp / fx:commanderSkill / audio:play` 等事件，在 boundary 层桥接一份进 `enqueue()`（3D 后端激活时）。
3. 音效不变：仍由 `audio.js` 统一播放，3D 后端不碰音频（后续可选做 3D 位置音源，列入 backlog）。
4. `enqueue()` 通道的类型契约已在 `types/battlefield-renderer.ts` 定义，补充本计划使用的事件字面量类型即可；`tsconfig.rendering.json` 的 typecheck 必须保持通过。

### 5.3 事件清单（v1 最小集）

`attack {presentation, attackerId, targetId, crit}`、`unitDied {unitId}`、`heal {unitId}`、`rankUp {unitId}`、`moraleChanged {unitId, level}`、`commanderSkill {commanderId, tileKey}`、`explosion {tileKey, scale}`、`screenShake {intensity}`、`recruit {unitId}`、`weatherChanged {weather}`。将领专属特效（18 名指挥官，`commander/fx/*`）v1 统一走 `commanderSkill` 通用 3D 表现（徽记 + 光柱 + 属性色粒子），逐个定制列入 backlog。

## 6. 模型与动画资产计划

### 6.1 资产清单

- **10 基础兵种**：步、骑、炮（野战炮）、碉堡、岸防炮、无人机、驱逐舰、巡洋舰、潜艇、航母。
- **12 专精变体**：卫戍/突击步兵、轻/重骑兵、野战炮/火箭炮/防空炮、防空/反潜驱逐舰、制海/支援巡洋舰 —— 实现为**同族模型的部件/涂装变体**（换炮管、加装甲板、改涂装条带），不为每个专精单独建模。
- **18 指挥官**：v1 用"专属披风/旗徽 + 单位底座光环 + 头像铭牌"在单位上标识（立绘 png 贴旗面），不建独立 3D 人物；独立指挥官模型列入 backlog。
- **地形装饰**：平原/森林/山地/城市/村庄/港口/机场、战壕与高射机枪工事、桥梁渡口；水面（含岸线过渡）。
- **阵营表现**：阵营九色板（`rules/camps.js FACTION_PALETTE`）→ 模型主材质顶点色/涂装 + 旗帜布料（plane 顶点波动，复用现有旗帜 SVG 图集贴图）。

### 6.2 双轨生产管线

**轨道 A（M1–M3 默认）：程序化基元建模**

- `js/rendering/three3d/models/` 每兵种一个工厂函数，Three.js 基元拼装 + `flatShading`，50–300 三角面/单位；
- 全程 InstancedMesh/合并几何（同兵种同阵营静态部件合并），保证满编 60+ 单位时 draw call < 150；
- 原型（§9）即轨道 A 的美术基线，先评审风格再量产。

**轨道 B（后续升级）：GLTF 资产管线**

- 资产规范：`.glb` + Draco/meshopt 压缩，每兵种 ≤ 30KB，贴图 512² atlas，LOD0/LOD1 两级；
- 动画规范：命名轨 `idle / move / attack / hit / death`（+海军 `sail / submerge`），30fps，根骨不位移（位移由 motion 参数驱动）；
- 加载：`GLTFLoader` + 资产清单 `asset-manifest` 哈希缓存戳（复用 `tools/generateAssetManifest.mjs` 模式）；Actor 抽象不变，模型源从"工厂函数"换成"GLTF 克隆 + AnimationMixer"，特效挂点（炮口/甲板/旗帜座）用命名空节点约定；
- 采购/外包建议：低多边形战棋风格套件 + 逐兵种定制，验收以原型截图风格为准。

### 6.3 动画系统

- `UnitActor` 状态机：`idle / moving / attacking / hit / dead`，迁移由快照 diff（新状态字段）与 `enqueue` 事件驱动；
- 时间轴：全部以快照 `startedAtMs` 绝对时间为基准插值，不做累积式动画 —— 与游戏回放机制兼容；
- 代码动画原语：路径 hop/roll（步/骑/炮各异）、炮管后坐、舰船摇晃与下沉、无人机悬停正弦、旗帜顶点波动、浮尘/尾迹；
- GLTF 阶段映射到 AnimationMixer 同名 clip，crossfade 0.15s。

## 7. 特效与环境计划

- **命中/爆炸**：Points 粒子爆发 + 扩张冲击波环 + 瞬时 PointLight + 相机震动（`fx:screenShake` 强度映射）；
- **弹道**：发光拉伸体/抛物线网格 + 拖尾（TrailRenderer 式 ribbon）；鱼雷 = 水下航迹 + 水柱；
- **近战**：武器挥砍扇形弧光（加色混合面片）+ 命中闪光 sprite；
- **状态**：治疗上升光粒、晋升金星爆发、招募落地光圈、士气▲▼ 头顶标记（Sprite）；
- **浮字**：伤害/治疗/金币 canvas-texture sprite，暴击金色放大 —— 与 Canvas 端 `drawDamageTexts` 同一数据源（`gameState.damageTexts` 进入快照或事件）；
- **天气**：晴（暖光+薄雾）、雨（实例化雨线 + 地面溅落 + 光照转冷）、雾（距离雾 + 漂移雾团面片）、风（粒子流痕 + 旗帜波动增强）—— 数据来自快照新增 `weather` 字段；
- **水面**：顶点微波 + 岸线泡沫带 + 舰船只尾流；
- **昼夜**：v1 固定白昼暖调；昼夜循环列入 backlog（原型已验证夜战氛围可行）；
- **性能档映射**：`high` = bloom + 全粒子 + 阴影 2048；`balanced` = 无 bloom + 粒子减半 + 阴影 1024；`low` = 不推荐 3D（引导回 Canvas）。

## 9. 设计原型说明（M0 交付物）

- 位置：`prototype/3d-battlefield/`，完全独立（不动游戏源码，仅 root 增加 `three` 依赖）。
- 运行：`node prototype/3d-battlefield/serve.mjs` → 浏览器打开 `http://127.0.0.1:8321/prototype/3d-battlefield/`。
- 内容：半径 4 的六棱柱棋盘（平原/森林/山地/浅水/深水/城市）、红蓝双方 8 个单位（步/骑/炮/碉堡 vs 战舰/潜艇等）、自动演示循环（炮击对轰、骑兵冲锋、鱼雷攻击、近战突击）、可交互（选中/移动/攻击/轨道相机）、昼夜切换、伤害浮字、HP 环、阵营旗帜。
- 用途：作为美术方向与特效词汇的**评审基线**；M2/M3 的量产以此为视觉标准。原型代码不进入主包，但模型工厂函数可迁移为轨道 A 资产。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 美术资产量失控（10+12+18+地形） | 进度 | 轨道 A 程序化打底先行全量；专精=部件变体；指挥官 v1 不做独立模型 |
| 特效事件化遗漏触发点 | 3D 模式特效缺失 | 以 `classifyAttackPresentation` 五类为主干 + `visualEventBridge` 清单逐个核对；M3 设"特效对照清单"人工验收 |
| 包体/性能 | 默认用户受影响 | three 独立 chunk 懒加载；性能档映射 + low 档引导回 Canvas；满编帧率纳入 M2 验收 |
| 快照字段不足（weather 等） | 3D 氛围缺失 | M1 先行补字段，对现有后端零影响（新增可选字段） |
| 输入手感（3D 透视下点选偏差） | 可用性 | raycast 命中格心吸附 + 悬停高亮 + 2.5D 锁定视角开关 |
| 测试不可 headless | 回归成本 | three loader 注入式单测（照 Pixi 测试模式）；渲染语义断言（Actor 数量/状态）而非像素断言 |

## 11. 依赖变更

- 新增：`three`（运行时依赖，独立 chunk）。可选：`postprocessing`（M4 bloom，独立 chunk）。
- 不新增构建步骤；Vite 配置仅加 manualChunks 与多页入口不变。
- 原型阶段：`three` 已随 M0 安装；若计划终止于 M0，卸载 `three` 即可完全还原。
