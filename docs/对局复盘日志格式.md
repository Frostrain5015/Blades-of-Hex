# 对局复盘日志格式

游戏在标准对局或战役结算界面提供两层 JSON：

- 默认的 `*.match-review.json` 采用 `blades-of-hex.match-review` 格式，是适合直接交给大语言模型的轻量复盘索引。
- 按需导出的 `*.match-full.json` 采用 `blades-of-hex.match-log` 格式，保存完整动作、当时可见信息和状态差异，用于深挖具体决策。

两个 schema 当前的 `schemaVersion` 都是 `1`。索引中的 `sequence`、`sequenceStart`、`sequenceEnd` 可以直接定位到完整日志的 `timeline[].sequence`，动作引用则定位到 `timeline[].actionId`。

## 第一层：复盘索引

复盘索引不包含完整地图和逐动作上下文，主要字段包括：

- `overview`：阵营总览、伤害、击杀、损失和表现最突出的单位。
- `controlTimeline`：逐回合单位占比、城市占比和等权综合控制，供结算页势力面积图和模型判断全局走势。
- `battleEvents`：按本局交战强度分布自适应识别的高强度回合，不使用固定交战次数阈值。
- `roundIndex`：每回合的动作序号范围、交战数和阵营统计。
- `keyEvents`、`unitHighlights`：占城、阵亡、目标变化和高影响单位。
- `layer.detailFile`：配套完整日志的文件名及定位方法。

通常先只上传这一层。模型若认为某个回合或某个单位值得深挖，再补充完整日志即可。

## 游戏内统计与导入

结算页的“查看对局统计”会直接读取当前结构化日志，提供：

- 类 AoE2 的 100% 堆叠势力面积图，可切换单位占比、城市占比和等权综合控制。
- 根据本局各回合交战强度分布自适应识别的“战役事件”高亮。
- 阵营击杀、阵亡、输出、承伤、恢复、占城与每次攻击效率。
- 单位击杀、输出、承伤、恢复和行动次数排行榜。

大厅右上角的“导入对局日志”支持 `*.match-review.json` 和 `*.match-full.json`。文件只在浏览器本地读取：轻量索引直接恢复统计视图，完整日志则重新计算统计，不会覆盖当前或下一局的记录。

## 第二层：完整日志

- `coverage`：`full-from-initial-state` 表示从开局开始记录；断线重连后只能得到 `partial-from-current-state`。
- `mode`、`participants`、`initialState`：对局规则、控制者和复盘起点。
- `timeline`：按 `sequence` 排序的动作与事件。
- `finalState`、`result`、`summary`：终局局面、胜负与统计汇总。
- `reviewGuide`：给分析模型的内置约束，尤其要求按当时可见信息判断。

## 动作与事件

`kind: "action"` 的条目包含：

- `actorCampKey` 与 `actorKind`：谁执行，以及是玩家、Grok AI、脚本还是远端控制者。
- `actionType` 与 `payload`：动作意图和关键参数。
- `decisionContext`：动作发生前该阵营可用于决策的信息。在迷雾模式下，`knownOtherUnits` 不包含隐藏单位。
- `outcome.changes`：动作前后的单位、据点、资源和全局状态差异。
- `accepted`：单机为 `true`；联机为服务器确认结果，`false` 表示该本地预测动作随后被权威状态回滚。

`kind: "event"` 用于伤害、阵亡、占城、战役目标变化等不一定与动作提交点同步发生的结果。

## 推荐提问方式

上传 JSON 后可以直接要求：

> 按时间线复盘这局。分别列出三次最佳决策、三次典型失误和关键转折；评价决策时只能使用对应 action.decisionContext 中当时可见的信息。最后给出下一局可执行的改进建议。如果参与者是 AI，再归纳可重复的错误模式，并指出应优先检查的脚本决策规则，不要只按最终胜负倒推。

日志包含完整终局信息和手牌结果，适合赛后私下复盘；若要公开分享，应先确认其中没有不希望公开的对局信息。

## 双 Grok 自动对局

仓库提供复用同一规则引擎和当前 `ai/grok.js` 的命令：

```powershell
npm run selfplay:grok -- --seed=my-test --output=artifacts/selfplay/my-test.match-full.json
```

命令会同时生成 `my-test.match-review.json`。也可以用 `--review-output=...` 单独指定索引路径。

常用参数：

- `--seed=...`：确定性对局种子；相同代码、参数和种子应得到相同的逻辑时间线。
- `--map=grand-island-2p`、`--fog=true`、`--difficulty=1`：地图、战争迷雾和 AI 难度。
- `--commander-p1=...`、`--commander-p2=...`：固定双方将领；省略时由当前 Grok 选择逻辑决定。
- `--max-rounds=25`：运行器保险上限；标准双人对局仍会在引擎的第 19 回合规则处正常判胜。
- `--time-scale=0.02`：只压缩动画及延迟结算的墙钟时间，不替换战斗规则。

标准地图中的中立阵营继续由现有 Claude 中立 AI 控制；两个玩家阵营均由当前 Grok 脚本控制。完整 JSON 的 `automation` 字段会明确记录这一点。
